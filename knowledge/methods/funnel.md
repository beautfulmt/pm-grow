# 漏斗分析

## 解决什么问题

用户从接触到完成目标要经过多个步骤，每一步都有流失。漏斗分析把路径拆成步骤，计算每一步的转化，定位流失最严重或最值得改善的环节，并通过分群找到原因线索。生命周期层面可以用 AARRR（获取、激活、留存、收入、推荐）作为大漏斗。

## 核心步骤

1. **定起点和目标行为**：如"浏览商品详情 → 加入购物车 → 提交订单 → 支付成功"。
2. **定义每一步的口径**：用哪个事件、是否要求按顺序完成、时间窗多长、允不允许跳步、按用户还是按会话计数。
3. **算转化**：各步转化率和整体转化率；分别标出流失绝对量最大和转化率最低的步骤（两者常常不是同一步）。
4. **分群对比**：按渠道、新老用户、设备、地区、版本拆分，看差异集中在哪里。
5. **配定性证据**：会话回放、用户访谈、客服反馈，解释为什么流失。
6. **估改善价值**：某一步提升对最终结果的影响，结合改动成本排序。
7. **改动后验证**：用实验或前后对比验证，注意季节和渠道结构变化的干扰。

## 适用条件

- **适合**：路径清晰的转化问题，如注册、激活、下单、付费、表单提交。
- **前提**：关键步骤有可靠埋点，用户标识能跨步骤关联。
- **换用或简化**：路径高度发散的产品（内容浏览、工具类）更适合路径分析和[留存与同期群](retention-cohort.md)；数字异常时先做[指标异动诊断](metric-diagnosis.md)。

## 误用与反例

- 只看整体转化 → 分群看，平均数常掩盖某个渠道或版本的问题。
- 埋点重复上报或跨设备断裂造成"假流失" → 先核对数据质量。
- 只盯转化率最低的一步 → 同时看流失绝对量和改善可行性。
- 漏斗前段提升了就算成功 → 看最终结果和护栏，确认后段质量没有变差。

## 行业变形

- [企业服务 SaaS](../industries/saas.md)：漏斗跨线上和销售流程（线索、商机、试用、签约），周期长、样本少，按账户计算。
- [电商与零售](../industries/ecommerce.md)：搜索、推荐、活动、广告入口分别建漏斗，大促期间单独看。
- [游戏](../industries/gaming.md)：新手引导以关卡或任务步骤为单位，并和付费漏斗结合看。
- [金融科技](../industries/fintech.md)：开户和授信漏斗里的风控拒绝单独拆出，拒绝和体验流失分开分析。
- [教育](../industries/education.md)：试听到正价课的转化包含顾问跟进，线上数据要和销售记录合并看。

## 不同阶段怎么用

- **newcomer 新人**：照着用。按导师给定的步骤搭漏斗，逐步核对口径，找出流失最大的一步。
- **independent_pm 独立 PM**：会选会改。自主定义漏斗、做分群，提出可验证的改进假设。
- **senior 资深**：判断漏斗是不是合适的分析框架，识别口径和选择偏差，避免局部优化伤害整体。
- **expert 专家**：沉淀本领域的标准漏斗和口径，供团队复用。
- **lead 负责人**：用漏斗统一跨团队对转化问题的认识，明确每一段的负责人。
