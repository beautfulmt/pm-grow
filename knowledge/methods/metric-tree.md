# 指标树与北极星指标

## 解决什么问题

团队面对一堆指标，却说不清该盯哪个、各自的工作怎样影响整体。指标树把一个顶层结果（北极星指标或业务目标）按数学关系或因果关系拆到团队能直接影响的输入指标，再配上护栏指标防止伤害。它用来设目标、解释变化和分配责任。

## 核心步骤

1. **选顶层**：北极星指标体现用户获得的核心价值，并领先于营收（如"每周完成学习任务的学生数"）；同时写出它对应的业务结果。
2. **拆解**：
   - 数学拆解：如 GMV = 访客数 × 转化率 × 客单价；活跃用户 = 新增 + 留存 + 回流。
   - 驱动拆解：哪些用户行为推动顶层，先标为假设，再用数据检验相关性。
3. **定义口径**：每个指标写清计算方式、时间窗、人群、数据源和更新频率。
4. **区分类型**：结果指标（滞后）、输入指标（团队可影响）、护栏指标（不能恶化，如投诉、退款、性能）。
5. **映射责任**：哪个团队负责哪些输入指标，检查有没有两个团队在优化互相冲突的指标。
6. **定期校准**：检查输入指标的变化是否真的带动了顶层，不成立就调整树。

## 适用条件

- **适合**：设定目标、季度规划、搭建数据看板、解释指标变化。
- **前提**：有基本的数据口径和埋点；口径不清时，先整理口径再建树。
- **换用或简化**：早期产品先盯一两个代表价值的关键行为指标；单次异动排查用[指标异动诊断](metric-diagnosis.md)。

## 误用与反例

- 北极星选了虚荣指标（如累计注册数）→ 选反映价值交付、能被用户行为推动的指标。
- 只做数学拆解，以为每个因子都能独立优化 → 标出因子间的相互影响（如提客单价可能压低转化）。
- 没有护栏 → 每个优化目标至少配一个反向检查指标。
- 各团队口径不一、数字对不上 → 指标定义集中维护，变更留记录。

## 行业变形

- [教育](../industries/education.md)：学习效果滞后且难测，用过程指标做代理时，定期检验它与效果的关系。
- [企业服务 SaaS](../industries/saas.md)：顶层常是收入留存或活跃账户，输入指标按账户而非个人计算。
- [内容/社区/社交](../industries/content-community.md)：同时设供给、消费、社区健康三类指标，以负反馈和举报作护栏。
- [广告与商业化](../industries/ads-monetization.md)：收入指标与用户体验护栏、广告主效果三条线一起看。
- [中后台与内部系统](../industries/internal-platform.md)：顶层是业务效率或差错率，和业务方共同定义。

## 不同阶段怎么用

- **newcomer 新人**：照着用。画出所负责功能的指标与上层目标的关系，说清每个指标的口径和数据来源。
- **independent_pm 独立 PM**：会选会改。为自己的方向设定输入指标和护栏指标，用树解释一次指标变化。
- **senior 资深**：判断北极星和拆解是否在误导团队，提出调整；处理团队之间的指标冲突。
- **expert 专家**：建立本领域的标准指标体系和口径。
- **lead 负责人**：用指标树设定组织目标和责任分工，定期检验树是否依然有效。
