# 埋点与数据需求

## 解决什么问题

常见的情况是：上线后才发现关键行为没记录、同一个事件有三种名字、指标口径和埋点对不上，复盘只能靠猜。埋点与数据需求把"上线后要回答什么问题"提前写成需求：要看哪些指标、由哪些事件和属性计算、在哪里采集、怎样验收，让数据和功能一起设计、一起验收。

## 核心步骤

1. **从决策倒推**：先写上线后要回答的问题和要看的指标（主要指标、护栏指标、诊断指标），再决定采集什么。
2. **定义指标口径**：每个指标写清分子、分母、人群、时间窗口和去重规则，并和数据同学对齐。
3. **设计事件与属性**：
   - 用统一的命名规范，如"对象 + 动作"。
   - 会变的值放进属性，不放进事件名。
   - 同一个属性在所有事件里含义一致。
4. **确定采集位置**：区分客户端采集和服务端采集。支付成功、订单状态这类以服务端记录为准的事实，不要靠前端点击去推断。
5. **写进需求文档**：在 PRD 里列埋点清单，包括事件、触发时机、属性、数据类型、示例值和负责人，并标出隐私和授权要求。
6. **验收与监控**：
   - 上线前在测试环境逐条核对。
   - 上线后检查数据量、缺失率和异常值。
   - 实验场景另外检查分组比例是否正常。
7. **维护埋点字典**：记录版本和变更，废弃的事件标明停用日期，避免新旧口径混用。

## 适用条件

- **适合**：新功能上线、实验设计、搭建指标体系、数据口径出现分歧、复盘发现数据缺失之后。
- **前提**：知道上线后要回答什么问题，有数据或研发同学配合实现和验收。
- **换用或简化**：
  - 还没想清楚要看什么指标：先用[指标树](metric-tree.md)。
  - 只是小改动：在 PRD 里写清一两个关键事件和验收方式即可。
  - 要做对照实验：按[A/B 实验](ab-test.md)补齐分流和护栏指标的记录。

## 误用与反例

- "先全埋了再说" → 从要回答的问题倒推，只埋少量核心事件，但属性要完整。
- 事件名里放日期、版本或具体值 → 这些放进属性，事件名保持稳定。
- 用前端点击代替业务结果 → 支付、下单、审核通过等以服务端事实为准。
- 只写事件，不写口径 → 指标的分子、分母和时间窗口要和数据同学书面对齐。
- 上线后才验收埋点 → 在测试环境逐条核对，上线当天再看一次数据量。
- 采集和需求无关的个人信息 → 只采集回答问题所需的最少数据，并按隐私和授权要求处理。

## 行业变形

- [电商与零售](../industries/ecommerce.md)：订单、支付、履约和售后状态以服务端为准，渠道和活动来源要贯穿整条链路。
- [内容、社区与社交](../industries/content-community.md)：曝光、点击、消费时长和互动要区分推荐位和内容来源，治理动作也要留痕。
- [企业服务 SaaS](../industries/saas.md)：事件同时带账户和用户两层标识，区分管理员配置和成员使用。
- [广告与商业化](../industries/ads-monetization.md)：请求、展示、点击、转化和计费的口径要能逐层对账，并注意归因窗口。
- [教育](../industries/education.md)：学习行为数据涉及未成年人时，按儿童个人信息保护要求取得授权，并尽量少采集。
- [AI 产品](../industries/ai-product.md)：记录模型、提示词和工具的版本，以及用户采纳、修改和纠错的行为，方便按版本评估。
- [开发者与工具类产品](../industries/developer-tools.md)：以服务端的调用结果为准定义"首次成功"等激活事件，按 SDK、语言、版本和错误码拆分。

## 不同阶段怎么用

- **newcomer 新人**：照着用。按导师给的模板为一个小功能写埋点清单，和数据同学逐条确认口径。
- **independent_pm 独立 PM**：会选会改。从上线后的决策倒推埋点，主导验收；发现口径问题时，能定位到具体的事件或属性。
- **senior 资深**：判断数据上的投入值不值得，推动跨模块统一命名和口径，避免指标体系各自为政。
- **expert 专家**：建立本领域的事件规范、指标字典和数据质量检查清单。
- **lead 负责人**：把埋点验收纳入上线标准，明确谁负责维护数据字典。

## 出处

- Ron Kohavi, Diane Tang, Ya Xu，《Trustworthy Online Controlled Experiments》, Cambridge University Press, 2020：第 13 章 Instrumentation，以及数据丢失导致的样本比例偏差。
- Segment（Twilio）文档, "Data Collection Best Practices"：跟踪计划、"对象 + 动作"的命名方式与属性规范。
