# 团队培养

## 解决什么问题

带人的 PM，产出取决于团队的判断质量，而不是自己多做了多少。团队培养帮助负责人以及带新人的资深 PM、专家，根据成员在具体任务上的成熟度调整指导方式，给出具体反馈，逐步授权，并营造让成员能成长、敢说真话的环境。按[能力模型](../../growth/abilities.md)的约定，这张卡评价的是用户本人的带人行为；讨论具体成员时，聚焦用户自己可以怎么做。

## 核心步骤

1. **了解成员**：职责、目标、强项与成长点、偏好的工作方式；按能力项分别判断，不给整体打标签。
2. **判断任务相关成熟度**：同一个人在不同任务上成熟度不同。成熟度低时多指导、给结构；高时多授权、给目标。
3. **设定期望**：明确目标、成功标准、决策权限和检查点，并书面确认。
4. **选择支持方式**：示范 → 一起做 → 指导下独立做 → 独立做并定期回顾，逐步放手。
5. **给具体反馈**：描述具体行为及其影响，再说期望；在关心个人的同时直接指出问题；表扬及时、纠正私下。
6. **建立机制**：一对一、评审、复盘、知识分享；保护心理安全，鼓励提出不同意见、承认错误。
7. **定期回顾成长**：对照能力和阶段确认进展和下一步练习，为成员找合适的挑战机会。

## 适用条件

- **适合**：带团队的负责人、带新人的资深 PM 或专家、组建新团队。
- **前提**：用户对成员有一定的授权或指导责任。
- **换用或简化**：只是一次性带新人完成任务时，取第 4、5 步即可；与上级的关系用[向上管理](managing-up.md)。

## 误用与反例

- 对所有人用同一种方式 → 按人和任务调整。
- 授权变成放任 → 授权的同时约定目标、边界和检查点。
- 反馈只有"挺好""不行" → 描述具体行为、影响和期望。
- 把成员能力当固定标签 → 看具体任务上的表现和变化。
- 替成员把活干完 → 留出试错空间，用提问引导。

## 行业变形

- [企业服务 SaaS](../industries/saas.md)：新人尽早接触客户，培养内容包含客户沟通和行业知识。
- [AI 产品](../industries/ai-product.md)：领域变化快，团队需要持续学习机制和共同的评测方法。
- [中后台与内部系统](../industries/internal-platform.md)：成员需要懂业务流程，安排跟岗和业务轮岗。
- [硬件/IoT/工业制造](../industries/hardware-iot.md)：跨学科协作多，培养覆盖供应链、工程和认证常识。

## 不同阶段怎么用

- **newcomer 新人**：了解即可；借此理解导师和上级的指导方式，主动说出自己需要的支持。
- **independent_pm 独立 PM**：带实习生或新人时，先练示范和具体反馈两步。
- **senior 资深**：照着用。带新人完成真实任务，判断何时放手，用具体反馈帮助对方成长。
- **expert 专家**：会选会改。通过评审、方法输出和辅导培养领域人才，不一定承担管理职责。
- **lead 负责人**：设计团队结构和培养体系，规划成员成长路径，平衡绩效与发展；判断何时用机制替代个人辅导。
