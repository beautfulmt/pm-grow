# 路线图与 OKR

## 解决什么问题

团队需要知道接下来往哪走、为什么、怎么判断走对了。OKR 用目标（Objective，定性的方向）和关键结果（Key Results，可衡量的成果）对齐方向；路线图把实现目标的主要投入按时间或优先级排开，让相关方理解计划与依赖。两者结合，让计划围绕结果而不是功能清单展开。

## 核心步骤

1. **从战略到目标**：明确本周期要推动的业务或用户结果（参考[战略选择](strategy-choice.md)和[指标树](metric-tree.md)）。
2. **写 OKR**：目标定性、有方向感；关键结果可衡量、描述成果而非任务（"新用户首周完成核心任务的比例提升到 X"，而不是"上线新手引导"）；每个目标配少量关键结果。
3. **写路线图**：
   - 按结果或问题组织主题，而不是罗列功能。
   - 用"现在 / 接下来 / 以后"（Now/Next/Later）表达确定性逐级降低，远期少写精确日期。
   - 标注依赖、关键决策点和背后的假设。
4. **分层沟通**：给管理层看主题和结果，给研发看近期范围，给销售和客户看承诺边界。
5. **定期检视**：按周或双周跟进关键结果，按月或季度根据新证据调整路线图，并记录调整理由。
6. **周期结束复盘**：哪些关键结果达成、为什么，计划与实际的差距说明了什么。

## 适用条件

- **适合**：季度或年度规划、跨团队协调、对外沟通方向。
- **前提**：有上一层的战略或目标可以承接；没有时先和上级对齐方向。
- **换用或简化**：早期探索型团队用短周期、少目标；交付承诺强的业务（B 端合同、硬件）在路线图中区分承诺项和计划项。

## 误用与反例

- 关键结果写成任务清单 → 改写为可衡量的结果。
- 路线图写满精确日期的功能 → 远期用主题表达，按确定性分层。
- OKR 与绩效强绑定导致目标保守 → 区分挑战型目标和承诺型目标。
- 一年不调整 → 定期按证据调整，并公开理由。

## 行业变形

- [企业服务 SaaS](../industries/saas.md)：对外路线图会被销售当作承诺引用，明确哪些是承诺、哪些是方向。
- [硬件/IoT/工业制造](../industries/hardware-iot.md)：路线图受研发和量产节点约束，时间计划比软件更刚性。
- [教育](../industries/education.md)：围绕学期和招生季排布，关键窗口错过就要等下一周期。
- [游戏](../industries/gaming.md)：按版本和赛季规划，内容产能是主要约束。
- [中后台与内部系统](../industries/internal-platform.md)：与业务方的年度规划对齐，并公开排期规则。

## 不同阶段怎么用

- **newcomer 新人**：照着用。理解团队 OKR，能说明自己的工作对应哪一条关键结果。
- **independent_pm 独立 PM**：会选会改。为负责的方向写 OKR 和路线图，并按证据调整。
- **senior 资深**：判断目标设置是否合理，处理跨团队依赖和资源冲突，向上沟通取舍。
- **expert 专家**：为领域方向提供关键结果的衡量方法和可行性判断。
- **lead 负责人**：从战略拆解组织 OKR，设计规划和检视节奏，保护团队专注。
