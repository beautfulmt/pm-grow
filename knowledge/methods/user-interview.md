# 用户访谈

## 解决什么问题

访谈用来获取用户真实的行为、情境和动机，验证或推翻我们对问题的假设。好访谈拿到的是过去真实发生过的具体事情，而不是对未来的承诺或对方案的礼貌夸奖。

## 核心步骤

1. **定学习目标**：列出最多三个想验证的假设，并写下"听到什么会让我改变判断"。
2. **按行为选人**：以"最近做过某件事"筛选，而不是按人口属性；有意加入流失用户、非用户和极端用户。
3. **写故事型提纲**：以"讲讲上一次……"开场，准备追问：当时在哪、用什么、下一步做了什么、为什么。
4. **访谈中多听少说**：追问具体例子；把夸奖和"我会用"转回过去的行为；请对方演示真实操作或拿出真实材料。
5. **分层记录**：原话、观察到的行为、自己的解读分开记，关键原话当场记下。
6. **当天整理**：每场写一页快照：人物、关键故事、痛点与机会、原话、意外发现。
7. **跨场综合**：按机会聚类，标注出现次数和反例，判断每条假设是成立、动摇还是推翻，决定下一步取证。

## 适用条件

- **适合**：问题界定、需求验证、流失原因、方案前的探索。
- **前提**：能接触真实用户或其可靠代理人。
- **换用或简化**：访谈样本小，擅长发现和理解；规模和频率交给数据或[问卷](survey-design.md)。用户难约时，先用客服记录、会话回放或跟岗观察补位。

## 误用与反例

- 问"你会不会用""愿意付多少钱" → 改问"上次遇到这个问题你怎么解决的，花了多少时间和钱"。
- 一开场就展示原型求反馈 → 前半程挖问题，后半程再测方案。
- 只访谈销售推荐的满意客户 → 补上流失用户和非用户。
- 把一两位用户的强烈意见当结论 → 用跨场综合和数据交叉检验。
- 记录只剩"用户觉得不方便" → 写下具体场景、原话和替代做法。

## 行业变形

- [企业服务 SaaS](../industries/saas.md)：采购者、决策者、使用者、管理员分别访谈，他们的诉求常互相冲突。
- [教育](../industries/education.md)：访谈未成年人需监护人同意且有成人在场；教师访谈避开授课高峰，课堂观察往往更可靠。
- [医疗健康](../industries/healthcare.md)：先确认知情同意和脱敏方式；医生时间稀缺，用跟诊观察替代长访谈。
- [中后台与内部系统](../industries/internal-platform.md)：用跟岗观察补足，同事描述的流程常和实际操作不同。
- [本地生活/出行/O2O](../industries/local-services.md)：去现场访谈商户和骑手、司机，安排在高峰之后。
- [出海与全球化](../industries/globalization.md)：用本地语言访谈本地用户，可借助本地研究伙伴；保留原话并标注译者。
- [开发者与工具类产品](../industries/developer-tools.md)：请开发者现场完成一次接入并出声思考，文档、报错和示例的问题会直接暴露。
- [政企与 ToG](../industries/gov-enterprise.md)：经采购单位安排后进行，基层使用者与处室负责人分开访谈，留意汇报式回答，结合跟岗观察。

## 不同阶段怎么用

- **newcomer 新人**：照着用。用导师给的提纲完成访谈，重点练"转回过去行为"的追问；访谈后请导师点评原话记录。
- **independent_pm 独立 PM**：会选会改。自己定学习目标和样本，临场调整追问，独立完成跨场综合。
- **senior 资深**：判断访谈是不是当前最便宜的取证方式；建立每周接触用户的持续节奏。
- **expert 专家**：沉淀本领域的提纲、招募渠道和常见误区，训练团队的追问能力。
- **lead 负责人**：把用户接触纳入团队节奏和评审要求，让决策材料里有一手证据。
