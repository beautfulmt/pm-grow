# 用户旅程图与服务蓝图

## 解决什么问题

只讨论单个功能时，容易忽略用户跨触点、跨时间的完整经历。旅程图把一个角色完成某个目标的全过程按阶段铺开，标出行为、想法、情绪、触点和痛点，帮助找到断点、交接处和机会。服务蓝图再往下画出前台员工、后台流程和支撑系统，适合涉及线下履约或多团队协作的服务。

## 核心步骤

1. **定范围**：一个角色 + 一个目标 + 明确的起止点（如"新店主从注册到完成首单"）。
2. **收集证据**：访谈、跟岗、客服记录、埋点路径。先用证据画，补充的假设单独标注。
3. **按用户视角划阶段**：如发现、比较、决定、使用、求助，而不是按内部部门命名。
4. **逐阶段填行**：用户行为、触点或渠道、想法与疑问、情绪高低、痛点、现有指标。
5. **标出断点**：情绪低谷、等待、重复录入、跨部门交接、没人负责的环节。
6. **需要时画服务蓝图**：在用户行为下方加前台动作、后台动作、支撑系统，用"可视线"分隔用户看得到和看不到的部分。
7. **选机会并认领**：把断点写成机会陈述，按影响和证据强度排序，每个关键断点指定负责人和下一步。

## 适用条件

- **适合**：多触点、长周期、线上线下结合、跨团队交接的问题；新人了解业务全貌。
- **前提**：至少有几位真实用户的经历或可回放的行为数据。
- **换用或简化**：单个页面的交互问题用[流程与状态设计](flow-state.md)；只想快速对齐时，画一行阶段加一行痛点即可。

## 误用与反例

- 画成"理想旅程" → 先画现状，目标状态另画一张。
- 一张图混合多个角色 → 每个角色一张，或在泳道中分开。
- 情绪曲线凭感觉画 → 标注依据，如访谈原话、投诉量、放弃率。
- 画完挂墙不落地 → 每个关键断点对应一个负责人和下一步动作。

## 行业变形

- [本地生活/出行/O2O](../industries/local-services.md)：必须画服务蓝图，线下履约（商户、骑手、司机）往往是体验主体。
- [医疗健康](../industries/healthcare.md)：旅程跨院前、院中、院后，涉及多个机构和角色交接。
- [企业服务 SaaS](../industries/saas.md)：画客户生命周期（评估、采购、实施、上线、续约），使用者与决策者旅程并行。
- [硬件/IoT/工业制造](../industries/hardware-iot.md)：纳入开箱、安装、配网、维修、回收等线下环节。
- [电商与零售](../industries/ecommerce.md)：售后和物流异常常是情绪最低点。

## 不同阶段怎么用

- **newcomer 新人**：照着用。用旅程图梳理所负责业务的全流程，作为理解业务的入口；导师检查每格是否有依据。
- **independent_pm 独立 PM**：会选会改。选对角色和范围，从图中找出最值得解决的断点并据此立项。
- **senior 资深**：判断何时需要完整服务蓝图、何时一张简图就够；用旅程图推动跨团队认领责任。
- **expert 专家**：维护本领域的标准旅程和服务蓝图，作为新成员上手材料。
- **lead 负责人**：用端到端旅程划分团队边界和共享指标，减少交接处无人负责。
