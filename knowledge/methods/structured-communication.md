# 结构化表达（金字塔原理）

## 解决什么问题

PM 的大量工作是让别人理解并采取行动。表达不清通常源于结构问题：结论埋在细节里、论据互相重叠、没说清希望对方做什么。金字塔原理提供一套组织方法：结论先行、以上统下、归类分组、逻辑递进；SCQA 帮助开场时把听众带进问题。

## 核心步骤

1. **明确对象与目的**：对方是谁、已经知道什么、关心什么、听完后希望对方做什么（决策、支持、知悉）。
2. **写一句话结论**：先回答"我想让对方知道或做什么"。
3. **用 SCQA 开场**：情境（Situation）→ 冲突（Complication）→ 问题（Question）→ 答案（Answer）。
4. **组织支撑论点**：三到五个要点，彼此不重叠、合起来足以支撑结论（MECE），按时间、结构、重要性或因果排序。
5. **每个要点配证据**：数据、事实或案例，注明来源和不确定性。
6. **结尾提出请求**：需要谁在什么时间做什么决定。
7. **按场合调整形式**：口头汇报、邮件或即时消息、文档、评审会的篇幅和细节不同；重要场合先讲给一位同事听。

## 适用条件

- **适合**：汇报、邮件、评审材料、向上沟通、跨团队对齐，任何需要对方理解并行动的场合。
- **前提**：自己已经形成判断；还在探索阶段时可以先发散讨论，形成判断后再结构化。
- **换用或简化**：即时消息里至少做到"结论 + 请求"两句；正式评审的准备用[方案评审与答辩](review-defense.md)。

## 误用与反例

- 按时间顺序讲自己做了什么 → 先讲结论和请求，再讲依据。
- 要点互相重叠或漏掉关键因素 → 用 MECE 检查分组。
- 把推测说成结论 → 区分事实、判断和假设。
- 结构完整却没有请求 → 结尾写清需要对方做什么。

## 行业变形

- [企业服务 SaaS](../industries/saas.md)：对客户管理层讲价值和投入回报，对使用者讲操作和变化。
- [中后台与内部系统](../industries/internal-platform.md)：对业务方用业务语言讲收益和变化，少讲技术实现。
- [医疗健康](../industries/healthcare.md)、[金融科技](../industries/fintech.md)：和专业人士沟通前先确认术语和证据标准。
- [AI 产品](../industries/ai-product.md)：向非技术相关方说明效果时，用具体样例和失败情况，而不是抽象的准确率。

## 不同阶段怎么用

- **newcomer 新人**：照着用。每次汇报前写一句话结论和三个要点，请导师检查结构。
- **independent_pm 独立 PM**：会选会改。按对象调整结构和细节，在评审和邮件中稳定做到结论先行。
- **senior 资深**：在复杂议题中抓住决策核心，照顾听众的不同立场。
- **expert 专家**：把复杂的领域知识讲给非专家，形成可传播的表达。
- **lead 负责人**：在组织沟通中设定方向和叙事，帮助团队成员提升表达。
