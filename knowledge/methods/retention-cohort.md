# 留存与同期群分析

## 解决什么问题

增长依赖用户持续获得价值。同期群（cohort）分析把用户按起始时间或特征分组，追踪每组随时间的留存，分辨"产品真的变好了"还是"新用户变多掩盖了问题"，判断产品是否形成了稳定价值，以及哪些早期行为与长期留存相关。

## 核心步骤

1. **定义留存**：选代表获得价值的行为（完成一次学习、下单、发布内容、使用核心功能），而不只是打开应用。
2. **选周期**：按产品的自然使用频率选日、周或月。
3. **建同期群表**：行是起始时间分组，列是第 N 期，格子是仍然活跃的比例。
4. **读曲线形状**：是否在某处之后趋于平缓（存在稳定留下的用户），新的同期群是否比旧的好。
5. **分群对比**：按渠道、首次体验、首周行为、地区、套餐拆分，找出留存高的群体特征。
6. **找关键行为**：比较留下和流失用户的早期行为差异，形成"激活行为"假设，再用实验验证因果。
7. **连回业务**：留存怎样影响生命周期价值、口碑和获客成本（见[单位经济模型](unit-economics.md)）。

## 适用条件

- **适合**：判断产品价值、评估改版的长期效果、优化新手期、分析流失。
- **前提**：数据周期足够长，用户标识稳定。
- **换用或简化**：新产品早期样本少，结合用户访谈和 Sean Ellis 的 PMF 调查（询问"如果不能再用会有多失望"）判断价值。

## 误用与反例

- 用总活跃数判断留存 → 总数会被新增掩盖，改用同期群。
- 留存定义为"打开应用" → 改为代表价值的行为。
- 把相关当因果（"加了好友的人留存高，所以强制加好友"）→ 用实验验证。
- 周期选错（低频产品看日留存）→ 按自然使用频率选周期。

## 行业变形

- [教育](../industries/education.md)：留存受学期、假期和考试影响，同期群按学期或报名批次对齐。
- [企业服务 SaaS](../industries/saas.md)：看账户留存和收入留存（含扩展与缩减），个人留存只作线索。
- [游戏](../industries/gaming.md)：版本更新和活动会改变曲线，分析时标出版本节点。
- [电商与零售](../industries/ecommerce.md)：复购周期因品类而异，按品类分开看。
- [本地生活/出行/O2O](../industries/local-services.md)：补贴期留存和自然留存分开看。
- [金融科技](../industries/fintech.md)：信贷业务用账龄（vintage）分析风险表现，原理与同期群相同。

## 不同阶段怎么用

- **newcomer 新人**：照着用。读懂同期群表，说出曲线形状意味着什么，核对留存定义。
- **independent_pm 独立 PM**：会选会改。自定义留存口径和分群，提出激活行为假设并设计验证。
- **senior 资深**：判断留存问题出在产品价值还是获客质量，给出不同对策。
- **expert 专家**：建立本领域留存的标准口径，总结周期性规律。
- **lead 负责人**：把留存作为业务健康度的核心指标，平衡增长投入与价值建设。
