# 知识获取与业务理解

知识用于支持当前判断。不要因为用户给出行业标签，就假装掌握其公司业务。

## 三层来源

| 层 | 获取方式 | 如何使用 |
|---|---|---|
| 通用方法 | 模型已有知识与可核验的产品实践、原作者方法资料 | 说明用途、步骤、适用条件、误用和验证方式 |
| 行业公开知识 | 按当前问题检索官方资料、产品文档、公开披露和研究原文 | 标注来源、时间、地域、产品阶段及适用范围 |
| 用户公司事实 | 用户明确提供的描述、文档、数据、流程和反馈 | 标注用户陈述或材料出处；推断请用户校正 |

公司事实不能由公开行业均值或竞争对手案例替代。阅读资料仅限用户提供或任务授权的范围，不扫描无关目录。外部检索尽量使用脱敏的通用问题，不把内部数据发到搜索查询。

## 工作顺序

1. 用已有材料形成一段业务理解：谁在什么场景需要什么、如何创造价值、用户负责哪段、当前未知是什么。
2. 找出会改变当前结论的知识缺口，决定查外部资料还是向用户补问。
3. 优先一手来源。搜索结果先打开原文再作精确归因；企业宣传和岗位描述保留各自局限。
4. 将可信结论、相反证据和待确认项分开写入业务背景或知识记录。记录来源定位、查阅日期与适用条件。
5. 新业务、版本变化、来源过期或冲突出现时重新核验。没有检索能力时说明尚未核验，保持一般性分析和取证建议。

变化快的市场信息、功能能力、价格及规则在用于具体决策前查证。来源冲突时核对日期、样本、定义与适用场景，不能为了收敛方案任意选一方。

## 参考库起点

以下英文一手页面于 2026-09-21 核验。后续引用具体内容时检查页面是否更新。它们提供不同类型的参考，不组成统一职级标尺。

| 来源 | 可借鉴部分 | 边界 |
|---|---|---|
| [SVPG：The Assessment](https://www.svpg.com/coaching-tools-the-assessment/) | 区分用户、数据、行业、公司业务与产品运行知识，按岗位所需选择辅导重点 | 作者的辅导方法，不直接搬用其分数给用户评级 |
| [SVPG：The Plan](https://www.svpg.com/coaching-tools-the-plan/) | 按具体知识或技能缺口安排实际练习 | 培养节奏需适配用户机会和任务 |
| [GitLab PM CDF](https://handbook.gitlab.com/handbook/product/product-management/product-cdf-competencies/) | 可观察的 PM 行为、责任范围、专家与负责人路径 | 特定企业环境，不能将其 KPI 或晋升条件通用化 |
| [腾讯：Development and growth](https://www.tencent.com/our-actions/social/development-and-growth/) | 专业与管理通道，分阶段学习与支持 | 公开发展介绍，未提供完整内部 PM 职级标准 |
| [腾讯：Weixin accessibility case](https://www.tencent.com/en-us/articles/2201509.html) | 根据真实用户反馈改进使用体验的案例 | 案例材料，不能据此推定全部产品方法 |
| [TikTok：User Growth PM](https://lifeattiktok.com/search/7524996624474753288) | 用户研究、数据与增长目标拆解的任务样例 | 国际业务岗位，不能代表国内全部 PM 或完整成长标准 |

不采用公共部门 PM 岗位框架作为本技能的成长基线。行业和组织差异必须通过实际任务校准。

## 知识卡最少保留

结论或方法、出处及日期、适用范围、关键假设、可能失效的条件、是否已核验。来自当前对话的方法归纳明确标记，不捏造外部来源。跨会话依靠这些可读记录接续，不承诺模型本身已经永久学会公司的全部业务。
