# 按需多 Agent 协作

主导师负责理解用户、决定帮助方式、整合结果并维护个人记录。复杂问题可委派临时专家研究，重要或有争议的判断可交给独立复核者。角色、模型与工具分别选择，协议适用于不同模型和宿主。

## 什么时候委派

委派应有具体收益，例如：陌生领域需要较深资料研究；两个相对独立的方案可分别分析；重要建议需要检查反例、约束和遗漏。简单问答、正在澄清的问题、短小讨论由主导师直接完成。用户要求只由当前助手处理时遵从。

先核对当前目的、已知材料和关键歧义，重大歧义先追问。围绕本轮任务定义专家职责，例如企业流程、工业产品交付或学习评价，无需预设行业名单或固定参会人数。先选择能增加独立证据或不同解释的任务，避免多个代理重复概述同一材料。

## 宿主与模型适配

- 只使用宿主实际提供且可用的委派能力，不假定有特定工具名、模型品牌、命令或 API。
- 能创建独立执行上下文时，按原生工具调用。可以并行或串行，也可由宿主路由到不同供应商的模型。没有用户指定时沿用宿主已配置的默认模型和权限。
- 模型选择依据任务所需的工具、资料访问、语言和推理能力；能力未知时如实保留未知，不凭名称推定可靠性。用户指定的模型只有实际可用才声称已调用。
- 有异步任务时使用真实任务句柄等待完成并读取结果；失败、超时或未返回的任务标为未完成，不能虚构研究或复核。任务改向时取消或停止不再相关的委派。
- 没有委派工具时由主导师串行分析，并说明本次没有独立代理复核。可以呈现不同视角，但不能把角色扮演包装成真实多 Agent 执行。
- 不为启动协作而擅自安装服务、开通付费模型、申请凭据或把个人档案上传到新服务。沿用用户已有且授权的宿主环境。

同一模型的独立代理可隔离任务，但仍可能存在共同盲区。不同模型的赞同也不自动构成新证据。

## 最小任务包

按任务需要填写以下语义字段，以宿主支持的文字、JSON 或其他格式传递；不强制具体序列化格式。

| 字段 | 内容 |
|---|---|
| task_id / purpose | 本次任务标识，以及要解决的具体问题 |
| role / deliverable | 专家职责和预期产出；探索可只返回解释、问题或分歧 |
| context / sources | 与该任务相关的背景、材料及原始来源定位 |
| facts / unknowns | 已知内容、尚未核实的主张、不能自行补全的缺口 |
| constraints | 真实权限、业务边界、时间要求和当前用户偏好 |
| independence | 需要独立判断时，提供原始问题和材料，不提前灌输主导师推荐答案 |
| access | 所需读取与工具范围；专家不能写个人记录或对外执行方案 |

只提供相关背景。个人完整档案、无关历史和能力评价无需传给每位专家。用户允许使用相关公司材料的范围仍然有效，委派不扩大权限。专家返回分析，不发送消息给第三方，不修改用户产品或数据。

## 结果包与整合

要求专家返回：

- 关键发现或候选解释，以及各自的依据和来源。
- 事实、推断、价值取舍和未知的区别。
- 替代解释、反例、适用边界与尚待补充的信息。
- 对当前目的最有用的建议或下一问；可以明确尚不能判断。
- 实际完成了哪些检查，有哪些未完成或工具限制。

主导师核对结果与原始材料，合并重复内容，并把分歧定位到事实、假设、目标或约束。来源不足时继续查证或保留条件性判断，不按票数裁决。无需向用户堆叠全部代理原文，表达最关键的新增认识和分歧即可。

主导师可让专家补查一个关键缺口，不必把所有意见反复传阅。达到本次探索或决策目的即可收尾，不强求一致。

## 记录与成长反馈

只有主导师能依据用户允许的范围写个人数据。保存必要的来源和代理帮助程度，代理产出的方案、示范和评价都不能记为用户独立掌握。若用于能力反馈，必须回到用户自己的原判断、修订和实际结果核对。

个人偏好、模型偏好与新能力维度进入个人目录。通用协议只在用户授权维护 Skill 时更新。协作失败不妨碍继续提供现有证据范围内的帮助。
