# 累计 HTML 知识手册

## 先提议，再生成

在一个概念已解释清楚、案例值得复盘、业务机制得到梳理，或开放问题值得持续跟进时，主动说明建议纳入的主题与价值，询问是否生成或更新。用户明确同意后才修改知识源并运行生成脚本。历史同意只覆盖当时范围，不自动授权后续所有专题。用户暂缓时，在学习计划记下本次主题，等有新增知识或用户要求后再提。

制作手册不能替代当前解题或成长验证，也不自动创建网站、托管或定时任务。

## 专题内容

专题结构由内容决定。概念解释可以保留定义、成立条件和易混淆之处；案例复盘可以保留实际经过、结果与解释；业务机制可以保留参与者、规则和因果关系；开放问题可以保留已知证据、竞争解释及待核对事项。这些形态可以混用，无须选择互斥的 `topic_type`。

有实际解题过程时，再保留关键判断、推导、步骤、边界、案例或可复用模板。没有确定判断时，明确当前不确定之处；没有步骤或模板时省略对应栏目。不要为了填表制造内容，也不要以“待补充”“暂无”充当正文。内容由当前讨论与核验资料整理，不把全部聊天堆进网页。

个人能力状态、同事评价和敏感内部细节默认不进入手册。内部来源可使用经用户确认的脱敏名称和定位，不生成外网链接或上传内容。来源不足的归纳明确说明局限。

## 数据与生成

在用户数据目录维护 `knowledge/handbook.json`。沿用 [handbook.json](../templates/handbook.json) 的书级结构和 `schema_version: 1`，专题字段按下方扩展。旧 JSON 可以直接生成，无须迁移或补字段。修改已有专题前先读原内容，以稳定 id 更新，不丢弃其他专题。

每个 topic 的共同最低要求：

- `id`：稳定的英文小写短横线 ID。
- `title`、`updated_on`：标题与实际更新日期（YYYY-MM-DD）。
- `sources`：来源列表。每条含 title、checked_on；公开来源带 http/https 的 url，内部或当前对话来源用 locator 说明出处，scope 说明适用范围。无外部来源时使用当前讨论的真实定位，不能虚构文章。
- 实质正文：至少有一个有效的 `sections` 段落，或有内容的旧正文栏位。仅有标题、标签、日期和来源不构成专题。脚本检查非空正文和字段类型，内容是否真实、有用仍需作者核对。

新增的可选字段 `sections` 是有序列表，每项为 `{"heading": "段落标题", "content": "段落正文"}`。标题和正文必须是非空字符串，正文中的换行会保留。按阅读顺序组织需要的段落，正文以纯文本显示，HTML 和 Markdown 语法不转成富文本。

所有旧字段继续支持，但均可按需省略：

| 字段 | 类型与用途 |
|---|---|
| `problem`、`context`、`judgment` | 字符串，问题、背景和当前判断 |
| `steps`、`boundaries`、`pitfalls` | 字符串列表，步骤、边界和常见误用 |
| `case`、`template`、`counterexample`、`next_action` | 字符串，案例、模板、反例和下一步；模拟案例明确标记 |
| `first_principles` | 对象，只填实际用到的 `goal`、`facts`、`constraints`、`mechanism`、`options`、`validation`，每个已提供的值为非空字符串 |
| `tags` | 字符串列表，便于检索 |

已提供的字段仍严格校验类型，不能用 `null` 代替字符串、列表或对象。可选旧文本为空白、列表为空或推导对象为空时不生成栏目；非空列表内的每项都必须是非空字符串。新的 `sections` 允许省略或使用空列表，但提供的每个段落必须完整。整篇正文为空时生成失败。

旧字段与 `sections` 可以混用。显示顺序保持旧栏目原顺序，然后依次显示 `sections`，最后显示来源。需要自由安排整篇顺序时，统一使用 `sections` 即可。所有段落都进入全文搜索，目录仍以专题为单位。

下面是一个只用 `sections` 的概念专题结构。内容与定位均为隔离示例，实际使用时替换成真实材料：

```json
{
  "schema_version": 1,
  "title": "产品知识手册",
  "updated_on": "2026-10-04",
  "topics": [
    {
      "id": "metric-and-goal",
      "title": "指标与目标的区别",
      "updated_on": "2026-10-04",
      "sections": [
        {
          "heading": "概念关系",
          "content": "目标描述希望改变的结果，指标提供可观察的信号。指标能否代表目标，取决于它与真实结果的关系。"
        },
        {
          "heading": "仍需核对的条件",
          "content": "点击率提高只能说明更多点击发生。若目标是帮助用户完成任务，还需核对任务完成情况及点击增加的原因。"
        }
      ],
      "sources": [
        {
          "title": "隔离示例讨论",
          "checked_on": "2026-10-04",
          "locator": "本文件的演示内容，不对应用户个人案例",
          "scope": "说明结构，不作为真实业务证据"
        }
      ]
    }
  ]
}
```

扩展其他内容时，保留共同元数据和真实来源，只替换正文。例如案例复盘可使用“事情经过”“结果”“解释的局限”；业务机制可使用“参与者与规则”“为什么会发生”“可能失效的条件”；开放问题可使用“已经知道什么”“有哪些解释”“什么证据会改变判断”。段落数量与名称由实际材料决定，不需要把这些示例全部填满。

确认内容范围后生成：

```sh
python3 <skill-dir>/scripts/build_handbook.py --input <data-dir>/knowledge/handbook.json --output <data-dir>/handbook.html
```

更新已有 HTML 时加 `--replace`；脚本会保存上一个版本。知识 JSON 修改前同样保留原文件，修正事实时保留来源和更新时间。脚本只处理用户已经确认的内容，运行命令不能代替获取同意。

## 显示与验收

使用 [handbook.html](../assets/handbook.html) 内联模板。单文件、无外部依赖，具备专题目录、全文搜索、无结果提示与打印样式。来源链接可外连，但离线阅读和搜索不依赖网络。

交付前实际打开生成的 HTML，检查正文、目录跳转、搜索与清空、打印全部专题、窄屏排版，以及无脚本错误和外部资源请求。没有浏览器或渲染工具时，说明未完成视觉验证，不能声称已检查布局。

只展示最终完整手册，提供真实绝对路径链接。示例和测试产物留在隔离目录，不作为用户个人知识手册交付。
