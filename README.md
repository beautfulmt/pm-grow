# pm-grow

面向在岗产品经理的通用实战导师 Skill。它从真实工作问题开始，帮助 PM 补齐上下文、形成有依据的判断、练习可迁移的方法，并通过后续案例验证成长。

当前版本：**v1.1.0**

## v1.1 的变化

- 开放探索可以以新理解、候选解释和未解问题收尾，目标与方案允许待定。
- 八项能力保留为基础，个人可注册额外成长维度并追踪证据。
- 日常交流有实质变化时保存可追溯摘要，下次按问题与业务情境接续；聊天记录与能力证据分别处理。
- 案例可关联发生时的项目、职责、约束和帮助程度，旧案例格式继续兼容。
- 复杂任务可按需委派专家研究或独立复核，协议适配不同模型与宿主；无委派能力时由单导师完成。
- 知识手册按内容选择栏目，支持概念、方法、案例、业务机制和开放问题。
- 记录工具使用同一数据目录锁，保护协作进程的读取、修改和写入。

## 它能做什么

- 新人暂时说不清业务或成长目标时，从最近一件任务开始引导。
- 在给具体建议前，主动识别会改变结论的关键信息，并帮助用户取证。
- 使用第一性原理检查目标、事实、约束、机制、选择与验证。
- 根据任务熟悉度，在导师示范、共同完成、独立尝试之间切换。
- 记录用户自己的判断、得到的帮助、修改和结果，避免把模型示范算作用户掌握。
- 在出现相似任务或积累足够独立案例后，主动做轻量回访和阶段回顾。
- 经用户确认后，把成熟方法整理为可离线搜索和打印的单文件 HTML 知识手册。

## 适用对象

覆盖在岗 PM 的不同阶段：

- 刚入职、还不熟悉业务的新人。
- 能独立负责功能或模块的产品经理。
- 负责复杂产品、跨团队协作或业务探索的资深 PM。
- 走专家路线或承担团队负责人职责的产品人。

经验和职级只用于了解起点。导师会按每项能力的真实表现、任务复杂度和独立程度调整帮助。

## 工作方式

一次完整的导师过程通常包含：

1. 还原具体任务、用户和业务背景。
2. 主动补齐会影响结论的上下文。
3. 从目标、事实、约束和机制推导选择。
4. 给出当前可执行的建议与验证方式。
5. 提炼一条可迁移方法。
6. 在后续相似任务中检查用户能否独立使用。

简单问题会简短处理，复杂决策才展开完整推导。用户可以选择先看示范、一起完成，或自己先做再接受反馈。

也可以直接说“今天只探索这个现象，不急着给方案”或“这次只给建议，不安排练习”。这类偏好按用户说明的范围保存在个人记录里，随后可以随时调整。模型仍会先澄清影响理解的重要歧义。

## 按需多 Agent

主导师负责理解诉求、整合结果和维护个人记录。遇到陌生领域、可拆分的复杂问题或重要判断时，可委派临时专家与独立复核者。角色随问题定义，模型和调用接口由宿主实际能力决定，未绑定任何供应商、模型名或代理 SDK。

专家只接收任务相关材料并返回发现、来源、不同解释和边界。主导师核对依据，不按赞同人数决定结论。子代理不写个人档案；宿主没有独立委派工具时，直接使用单导师流程并说明复核范围。此技能提供协作规则，独立 Agent 的运行由宿主负责。

## 八项能力底座

- 用户洞察与问题界定
- 业务与价值判断
- 方案设计与技术判断
- 数据分析与效果验证
- 策略取舍与规划
- 交付推进与风险控制
- 沟通协作与影响力
- 复盘学习与方法迁移

每项能力分别记录“未观察、需要支持、可以独立、复杂情境下稳定运用”。行业知识和团队负责人职责按真实任务叠加。

需要单独追踪“领域知识”等维度时，可在个人目录注册 `custom.domain-knowledge`，记录名称、定义和可观察行为。基础八项保持兼容，无需为每个人重新建立模型。调用示例和格式见 [能力模型](reference/能力模型.md)。

## 数据和隐私

个人档案默认保存在：

```text
~/pm-grow-data/
```

也可以设置 `PM_GROW_DATA_DIR`，或在对话中指定其他目录。一个数据目录对应一位学习者。

个人背景、公司业务材料、案例证据和生成的知识手册都保存在用户数据目录，**不会写进 Skill 源码仓库**。第三方代问、制品交付和 Skill 维护不会自动建立个人画像。

日常摘要保存在 `events/`，`growth-log.md` 提供可读索引。每个事件保留日期、来源、用户贡献、获得的帮助及未决事项；更正通过新事件关联旧记录。探索交流也可记录，不必等到三个案例。只有用户本人的有效尝试进入能力证据和回顾计数。

下次使用时先读取相关背景、偏好与近期事件，再继续未解问题。用户要求不记录时按当次边界处理。个人记录依赖实际文件读写，无法读写时会明确说明。工具示例：

```sh
python3 scripts/memory.py --data-dir /path/to/pm-grow-data recent --limit 5
python3 scripts/memory.py --data-dir /path/to/pm-grow-data append-event --input /path/to/event.json
```

具体字段、情境关联和纠错规则见 [档案与证据](reference/档案与证据.md)。

## HTML 知识手册

当出现值得保留的知识时，导师先列出建议沉淀的内容。得到用户明确同意后，再更新知识源并生成单文件 HTML。概念、方法、案例和开放问题可以按实际内容组织，无需硬填步骤或模板。旧手册 JSON 继续兼容，通用正文可使用 `sections`。

手册支持：

- 专题目录
- 全文搜索
- 无结果提示
- 手机阅读
- 打印样式
- 离线打开

手动生成命令：

```sh
python3 scripts/build_handbook.py \
  --input /path/to/pm-grow-data/knowledge/handbook.json \
  --output /path/to/pm-grow-data/handbook.html
```

更新已有手册时添加 `--replace`，脚本会保留上一版 HTML。

## 验证

脚本测试只使用隔离临时目录，不读取真实个人档案：

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖：初始化保护、学习者目录隔离、案例去重、撤回与示范过滤、能力扩展、情境快照、并发回顾和事件写入、接续与更正关联、灵活手册正文、内容转义和更新备份。行为场景还覆盖开放探索、单导师降级及按需独立委派。

## 设计边界

- 成长判断需要用户自己的实际尝试和可比较证据。
- 模型示范、用户表示理解、聊天次数和时间经过不能证明能力提升。
- 行业公开资料不能替代用户公司的真实情况。
- 外部职业框架与岗位要求用于参考任务和行为，不能直接充当统一晋升标准。
- 主动回访发生在当前对话或下次使用时。离线提醒需要宿主产品另外配置自动任务。
