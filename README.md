# pm-grow

pm-grow 是一个面向在岗产品经理的实战导师 Skill。

它从用户手上的真实工作问题开始：先把问题解决掉，再结合所在行业把用到的方法讲透，最后用用户自己的表现来确认成长。

当前版本：**v2.1.0**

## 适用对象

导师会根据每个人的阶段调整带法。阶段按实际职责和真实表现来定，不看头衔。

| 阶段 | 典型情境 | 导师怎么带 |
|---|---|---|
| 新人 | 刚入职或刚转岗，负责明确的功能、报表或文档 | 多示范，给清单，一次只练一个点 |
| 独立 PM | 独立负责一个功能或模块的全流程 | 和用户一起推导，追问推理过程 |
| 资深 | 负责复杂产品或一条业务线 | 做陪练，压力测试假设，必要时派 Agent 挑错 |
| 专家 | 在某个领域做深，输出方法和标准 | 同行式讨论，帮用户把经验沉淀成方法 |
| 负责人 | 对业务方向、资源和团队负责 | 思考伙伴，拆解组织问题 |

资深之后，专家和负责人是两条并行路线。导师不会默认把带人当作唯一的成长方向。

## 能解决哪些问题

内置 14 个高频场景：

- 需求判断
- 指标异动
- 方案设计与评审
- 优先级与规划
- 项目推进与风险
- 线上事故与客诉
- 协作分歧与向上沟通
- 用户研究
- 增长与新业务
- 竞品与市场
- 上线评估与复盘
- 功能下线与收缩
- 接手新业务
- 职业成长

每个场景都写明了以下内容：

- 必须补齐的上下文
- 推导路径
- 可用的方法
- 不同阶段各自关注什么
- 阶段检查点和反问
- 练习变式

## 方法论：通用底层加行业特性

方法论没有放之四海皆准的版本。pm-grow 按下面这条链路，把方法传递给用户：

```text
通用原理（37 张方法卡）→ 行业变形（15 个行业包）→ 你们公司的做法与约束 → 这一次怎么用
```

**内置行业包：**

- 教育
- B 端 SaaS
- 中后台与内部系统
- 内容、社区与社交
- 电商与零售
- 本地生活与出行
- 金融科技
- 医疗健康
- 游戏
- 硬件、IoT 与工业制造
- 广告与商业化
- 政企与 ToG
- 开发者与工具类产品
- AI 产品（可以和任意行业叠加）
- 出海与全球化（可以和任意行业叠加）

遇到没有内置包的行业，导师会结合用户提供的材料和公开资料，为这位用户生成一个个人行业包，并标注为“待核验”。

## 成长闭环

1. **阶段性反问。**问题定义后、选定方案后、行动或上线后，导师会确认问题是否真的解决了。给出方案时，导师会约定回访点，下次开场先问：“上次的问题现在怎么样了？”已经解决或放弃的问题不再追问；一个月没动静的问题，导师只问一次还要不要继续跟。
2. **两级告知。**每次实质任务结束时，导师会给出三部分反馈：
   - 【本次表现】引用你自己的产出，说清做到了哪一步。
   - 【能力变化】有跨问题的证据时，明确告诉你“X 能力从需要支持提升到可以独立”，并附上依据。
   - 【仍在练】给出具体的下一步。

   能力升级的证据门槛由脚本校验。导师的示范、你说“我懂了”，都不计入能力证据。证据必须针对这项能力本身；能力不能跳级，只有“未观察”可以在证据充分时直接升到“可以独立”；“可以独立”需要来自不同日期、不同问题的独立产出，“复杂情境稳定”还要跨越至少两周、包含新的证据，并经过独立复核（宿主没有委派工具时，如实标注为导师自查）。
3. **HTML 成长报告。**满足以下任一条件时，导师会主动提议生成：
   - 上次报告后，3 个不同的问题已有用户本人尝试
   - 距上次报告超过 2 周
   - 到达关键节点，比如问题解决、能力升级、上线或评审通过

   你也可以随时要求生成。你说“先不用”时，导师会暂缓：等出现新的问题和结果，或者再过两周才重新提议；也可以约定某天之后再说。报告包含三部分：
   - 最近学了什么、做了什么
   - 遇到了哪些问题，用什么方式处理，有没有解决
   - 哪些方面成长了，哪些方面还欠缺，并附各项能力在各阶段的全景
4. **焦点能力与间隔迁移。**你可以选 1–2 项想重点练的能力，导师会优先从中挑练习点，报告里单独呈现进展。导师示范过、但你还没独立用过的方法，隔一段时间再遇到合适的任务时，导师会请你先试一步。

## 回答档位

导师按问题的分量调整回答的长短：

- **快答：**只要结论或正赶时间时，几句话给出结论、依据和下一步，不展开方法讲解和练习。
- **标准：**日常的实质问题，解题、讲透一条方法、挑一个点练。
- **深度：**影响大、难以逆转的决定，展开证据、取舍和验证方式，并委派 Agent 复核。

你随时可以说“简单点”或“展开讲”。

## 多 Agent 与扩展

遇到重要决策时，导师会自动委派 Agent 做研究或复核，并告诉你派了谁、去做什么。内置 7 个角色：

| 角色 | 负责什么 |
|---|---|
| 行业研究员 | 补充行业事实和资料 |
| 用户研究员 | 研究用户与使用场景 |
| 数据分析师 | 分析数据、检验假设 |
| 竞品分析师 | 梳理竞品和市场 |
| 技术可行性顾问 | 评估方案的技术可行性 |
| 反方评审 | 专门挑错、找漏洞 |
| 成长复核员 | 在能力升级前独立复核证据 |

宿主没有委派工具时，由单个导师完成，并如实说明这一点。

方法卡、行业包、问题场景、Agent 角色、外部工具和 skill 都可以扩展：

- 技能级扩展：写进本仓库，所有人共享。
- 个人扩展：在自己的数据目录里登记，例如“以后竞品分析用某个 skill”。

详见[扩展机制](reference/extensions.md)。




## 数据和隐私

个人数据默认保存在 `~/pm-grow-data/`。也可以通过环境变量 `PM_GROW_DATA_DIR` 指定，或在对话中告诉导师用哪个目录。一个目录只对应一位学习者。

- 个人背景、公司材料、成长记录、报告和手册都保存在你自己的数据目录里，不会写进 Skill 仓库。
- 第三方代问、只交付制品、维护技能时，不建立个人档案。你说“这次别记录”时，导师也不会记录。
- 委派 Agent 时只传递与当前任务相关的材料，并做脱敏处理。Agent 不会写入你的个人记录。
- 首次建档时，导师会告诉你数据存在哪里。不小心记下了客户名或内部数据，可以让导师清除：先预览会改哪些文件、各改几处，你确认后再替换，日志只记次数、不存原文。云同步的副本和已经分享出去的文件不受影响，需要你自己处理。

从 v1 升级时，导师会提示你迁移数据。迁移前，旧文件会完整备份到 `legacy-v1/` 目录下。

常用命令：

```sh
python3 scripts/pmgrow.py --data-dir ~/pm-grow-data status          # 开场用的精简状态
python3 scripts/pmgrow.py --data-dir ~/pm-grow-data status --full   # 全部问题与回访
python3 scripts/pmgrow.py --data-dir ~/pm-grow-data redact --input redaction.json --dry-run
python3 scripts/pmgrow.py --data-dir ~/pm-grow-data handbook list
python3 scripts/pmgrow.py --data-dir ~/pm-grow-data migrate --dry-run
```

完整命令见 [scripts/CLI.md](scripts/CLI.md)。

## 验证

```sh
python3 -m unittest discover -s tests -v
```

脚本测试只使用隔离的临时目录，不会读取真实的个人档案。导师本身的表现用 [tests/evals/](tests/evals/README.md) 的评测题和评分标准来检验。

v2.1.0 发布验收：
- 120 项自动测试通过，其中有 8 周纵向模拟数据；评审时复现的问题逐项复测，24 项检查全部通过。
- 4 道新增行为的隔离演练达到通过标准：快答、首次建档告知、暂缓报告、长期未动的问题（含第二轮）。
- 报告和手册在 Chromium 下检查了目录、搜索、打印样式、无脚本阅读和 390/760/1360 像素宽度。
- 其余 7 道新题和 v2.0 的 18 道题本次没有重跑。演练发现的两处规则偏差已经修正，修正后的复跑情况和其他限制见 [v2.1.0 验收记录](tests/evals/results/2026-10-22.md)。

v2.0.0 的验收见[验收记录](tests/evals/results/2026-10-19.md)。这些检查不代表所有模型、宿主或真实业务效果都已经验证。

## 设计边界

- 成长判断依据用户自己的尝试和可比较的证据。
- 行业公开资料用作对照，你们公司的实际情况以你提供的材料为准。
- 阶段描述的是任务复杂度和职责范围，不等于任何公司的职级标准。
- 主动回访发生在当前对话或你下次使用时。如果需要离线提醒，要在宿主产品里另外配置自动任务。
