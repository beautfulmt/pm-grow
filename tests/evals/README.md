# 导师质量评测

脚本测试验证数据管道，这里的评测验证导师本身的表现：每次修改规则、场景或方法卡后，都应确认导师变好了，至少没有变差。

## 文件

- [cases.json](cases.json)：评测题。覆盖各阶段、各问题场景和多个行业，另有回访、报告时机与暂缓、不记录、陌生行业、升级门槛与复核、回答档位、长期未动的问题、焦点能力、清除敏感信息等专项题，以及跨会话的多轮题。
- [rubric.md](rubric.md)：评分维度与通过标准。
- `results/`：每次评测的结果记录。

题目结构由 `tests/test_eval_cases.py` 自动检查；题目内容的好坏仍靠前向演练和人工评分。

## 题目字段

| 字段 | 说明 |
|---|---|
| `id`、`stage`、`scenario`、`industry` | 题目标识、用户阶段、主场景和行业；不适用时写 `none` |
| `setup` | 运行前要在临时数据目录准备的状态 |
| `today` | 可选。第一个会话的日期，准备数据和答题时调用脚本都加 `--today` |
| `prompt` | 用户的第一句话 |
| `turns` | 可选。预设的后续用户回复，按顺序使用 |
| `expect`、`anti_patterns` | 整题的预期与反模式，只给评测者看 |

`turns` 中每一轮包含：

- `user`：预设的用户回复，逐字发送。
- `today`（可选）：这一轮开启新会话，并使用这个日期。
- `expect`（可选）：这一轮之后要核对的行为和数据。
- `note`（可选）：给评测者的处理说明，例如执行者偏离预设时怎么回应。

## 运行方式

1. **准备数据目录。**为每道题建一个临时数据目录，按 `setup` 用 `scripts/pmgrow.py` 写入前置记录和状态。不使用真实的 `~/pm-grow-data`。
   - 前置的能力升级要满足当前门槛：每条证据记录都带同一能力、未撤回的观察；不跳级（stable 只能从 independent 升上来）；升到 independent 的证据至少分布在 2 个不同日期；升到 stable 的证据跨度至少 14 天，含升到 independent 之后的新证据，并写 `review`。
   - 暂缓、报告等状态用对应命令准备，例如 `report defer --today <日期>`。setup 要求“暂缓之后才写入”的记录，必须在这条命令之后再写。
2. **前向演练。**由一个独立的执行者（宿主的 Agent 或子代理，或一个新会话）来答题。只提供以下内容：
   - 技能目录路径：给一份不含 `tests/` 的导出副本，例如 `git archive HEAD | tar -x -C <副本目录>` 后删除其中的 `tests/`，或从工作区复制后删除。直接给仓库路径时，执行者可能读到 `tests/evals/cases.json` 里的预期答案，这样的结果不算独立。
   - 临时数据目录
   - 用户的第一句话（`prompt`）
   - 题目有 `today` 时，再加一句：“本会话的日期是 <today>，调用 scripts/pmgrow.py 时都加 `--today <today>`。”

   不提供 `expect`、`anti_patterns`、`turns` 和 `note`。
3. **多轮题。**评测者扮演用户，按 `turns` 的顺序逐字发送 `user`：
   - 不带 `today` 的轮次，在同一会话里继续。
   - 带 `today` 的轮次开启新会话：结束当前执行者，另起一个新的执行者。新执行者只拿到技能目录、数据目录、这一轮的 `user` 和新的日期说明，不拿到上一会话的对话，跨会话的接续只能来自数据目录。
   - 执行者偏离预设（例如没有提议焦点）时，按该轮 `note` 回应；没有 `note` 时，用最贴近题意的一句话回应，并在结果里注明。
   - 每一轮之后检查数据目录：用同一个 `--today` 运行 `status --full` 和 `recent`。核对两件事：一是新写的记录、问题状态、回访、焦点、暂缓等是否符合该轮 `expect`；二是执行者说“已记录”之前，记录是否已经写入并读回。
4. **评分。**评测者对照 `rubric.md` 和题目的 `expect`、`anti_patterns` 打分，同时检查临时数据目录里的记录是否符合预期。多轮题按 rubric 中的多轮计分方式处理。
5. **对比。**改动较大时，选同一批题，用改动前的版本再跑一遍做对比。
6. **记录与改进。**把结果写进 `results/YYYY-MM-DD.md`。没通过的题对应到具体的规则或文件，修改后重新跑这道题。
