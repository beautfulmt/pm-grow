# 导师质量评测

脚本测试验证数据管道，这里的评测验证导师本身的表现：每次修改规则、场景或方法卡后，都应确认导师变好了，至少没有变差。

## 文件

- [cases.json](cases.json)：评测题。覆盖各阶段、各问题场景和多个行业，另有回访、报告时机、不记录、陌生行业、升级门槛等专项题。
- [rubric.md](rubric.md)：评分维度与通过标准。
- `results/`：每次评测的结果记录。

## 运行方式

1. **准备数据目录。**为每道题建一个临时数据目录，按 `setup` 用 `scripts/pmgrow.py record` 写入前置记录。不使用真实的 `~/pm-grow-data`。
2. **前向演练。**由一个独立的执行者（宿主的 Agent 或子代理，或一个新会话）来答题。只提供以下内容：
   - 技能目录路径
   - 临时数据目录
   - 用户的第一句话（`prompt`）

   不提供 `expect` 和 `anti_patterns`。题目需要多轮时，由评测者扮演用户，按题意回应。
3. **评分。**评测者对照 `rubric.md` 和题目的 `expect`、`anti_patterns` 打分，同时检查临时数据目录里的记录是否符合预期。
4. **对比。**改动较大时，选同一批题，用改动前的版本再跑一遍做对比。
5. **记录与改进。**把结果写进 `results/YYYY-MM-DD.md`。没通过的题对应到具体的规则或文件，修改后重新跑这道题。
