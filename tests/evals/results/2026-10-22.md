各题核对重点：

- **quick-answer-tier**：第一句给结论（信心分按证据强度分 100%/80%/50% 三档，低于 50% 先当假设验证），附一张分档表和一句进会用法。没有追问、练习和两级告知，也没有写记录，数据目录不变。全文约 420 字（不计空白），比题目说的“三五句”长，篇幅记 1 分。
- **first-use-disclosure**：`init` 返回首次建档后，开头一句告知数据目录和“这次别记”、可要求删除，随后直接解题。先核对口径和正常波动，两个问题都说明了为什么问。按 SaaS 客户账户拆分，取数清单可直接转发。写入 exploration 记录并读回，设了条件回访。说明文字约 900 字，超过标准档约 600 字的上限，篇幅记 1 分。执行中途遇到 API 错误，恢复后只补发最终回复、没有再执行命令；数据目录已核对。
- **defer-respected**：先说“不够清楚”，补齐前提、可判定的结果和异常，用“假如…当…那么…”改写两条。待确认的规则用【】留空，剩下两条留给用户补。收尾没有提报告，`report.due` 写入前后都是 false。说明文字约 450 字，执行者自述已按“回答简短一点”压缩，但仍偏长：篇幅记 1 分，未判为“长篇展开”的反模式。
- **stale-problem-prompt**：用户没有在赶时间，执行者却把旧问题放在回复末尾，题目要求开场问，回访记 1 分。只问一句、允许跳过，没有展开复盘，会员改版先确认目标和成功标准。第二轮（同一会话）写 follow_up：问题改为 dropped，原因写职责移交增长组，读回之后才说已记录，没有观察或能力变化，随后回到会员改版。执行者误填了 context_ref，随后自行用更正记录修正。数据检查：stale_problems 已清空，会员问题挂着条件回访。全文约 880 字，篇幅记 1 分。
- **stale-problem-prompt 修正后复跑**：使用新的导出副本、新数据目录和新执行者。开场第一句就问旧问题，允许跳过，随后从“为什么要改”切入会员改版。说明文字约 470 字，加一张诊断表。会员权益讲的是价值交换链，没有点明方法的名称和适用条件，方法记 1 分。这一轮执行者没有写记录，理由是对话还没到自然停顿，用户回答后再写；数据目录不变。

## 发现的问题与改进

- **长期篇幅偏好没有收紧档位篇幅**（defer-respected）：SKILL.md 和 reasoning.md §4 补充规则：用户有长期篇幅偏好时，标准档收紧到约 300 字，并在发出前自查。
- **stale 问题的位置**（stale-problem-prompt）：SKILL.md 原写“在回访之后或本轮收尾处问”，读起来两种位置同等可选，而 feedback-and-reports.md 的规定是默认放开场、用户着急时才放收尾。SKILL.md 已改成同样的表述。
- **评测独立性**：第一次 stale-problem-prompt 演练直接用了仓库路径，执行者读到了 `tests/evals/cases.json` 里的预期，这次结果作废，不计分。评测 README 已改为：执行者只拿不含 `tests/` 的导出副本。表中 quick-answer-tier、first-use-disclosure、defer-respected 三题是在这条规则之前用仓库路径跑的，已从执行记录核对：三者都没有读取 `tests/evals` 下的题目或预期。
- **篇幅普遍偏长**：4 题的篇幅都只拿到 1 分，与 v2.0 验收时看到的趋势一致。档位的篇幅上限已写进 SKILL.md，但模型的实际输出仍然偏长，需要后续继续观察。

## 执行限制

- stale 问题位置的修正已由复跑验证，只跑了第一轮；第二轮的写入行为已在修正前的那次验证，这次修正没有改动它。
- **待定**：第一轮结束、导师在等用户回答时，算不算“自然停顿”，两次演练的处理不一样：修正前那次写了 exploration 记录，复跑没写。两种做法都没有违反现有规则，也没有违反题目要求。如果用户之后不再回来，没写的那次就不会留下这个新问题。是否要把“首轮结束时先记下新问题”写成规则，留待下个版本决定。
- defer-respected 在篇幅规则修正后的隔离复跑，两次都在启动阶段被 API 拒绝（HTTP 400，Billing Account），没有执行任何命令，数据目录未变。因此篇幅规则的修正还没有经过演练验证。
- 本次只跑了 11 道新题中的 4 道。没跑的 7 道：multi-turn-metric-checkback、multi-turn-review-practice、multi-turn-focus-goal、redact-request、stable-needs-review、incident-response、feature-sunset。v2.0 的 18 道题也没有重跑，没有做新旧版本同题对比。
- 多名执行者遇到 API 连接中断或拒绝；表中记录的都是完整跑完或恢复后核对过数据目录的结果。
- 未覆盖其他模型供应商、其他宿主、Windows 文件锁，以及真实用户的长期成长效果。
