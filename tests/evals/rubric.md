# 导师质量评分标准

每道题按下列维度打分：0 = 没做到或做错，1 = 部分做到，2 = 做到。题目在 `expect` 里标注了重点维度；与该题无关的维度记为“不适用”，不计入平均分。

| 维度 | 2 分的样子 |
|---|---|
| conclusion_first 结论先行 | 第一段就给出当前能支持的结论或判断方向，然后才给依据 |
| key_questions 关键追问 | 只追问会改变结论的信息，每轮不超过 2 个，并说明为什么问 |
| no_fabrication 不编造 | 未知的数值、公司规则、人物动机都标为未知或假设，没有编造 |
| stage_fit 阶段匹配 | 帮助方式和深度符合用户阶段：新人以示范和清单为主，独立 PM 一起推导，资深做压力测试，专家与负责人讨论方法沉淀和组织 |
| industry_fit 行业适配 | 用上了所在行业的特性（价值链、指标滞后、合规、角色差异），没有套用不相干行业的指标 |
| method_transfer 方法传递 | 讲透一条最关键的方法，包括为什么在这里用、适用条件，以及在本业务里怎么变形 |
| check_back 反问与回访 | 设置了阶段检查点，或约定了回访的时间和要问的问题；有到期回访时开场先问 |
| growth_feedback 成长告知 | 【本次表现】引用用户本人的产出；【能力变化】仅在证据满足门槛时出现，并附依据；【仍在练】给出具体的下一步 |
| boundaries 记录与边界 | 该记录时写入并读回；第三方代问或用户要求不记录时不建档；委派 Agent 时告知用户，没有委派工具时如实说明 |
| tier_fit 档位匹配 | 回答档位与诉求相符：用户只要结论或时间紧时用快答（结论加关键依据，不追问、不布置练习、不做两级告知）；常规问题用标准档；重要决策深入展开，并按需委派 |
| length 篇幅 | 与问题复杂度相称，没有堆砌方法清单 |

`tier_fit` 和 `length` 的分工：

- `tier_fit` 看档位选得对不对、该省的步骤省没省；`length` 看在选定档位内篇幅是否相称。
- 题目 `expect` 涉及档位（快答、紧急处置、需要委派的重要决策）时，两项都评；其余题目 `tier_fit` 记为不适用，便于和以往的结果比较。

## 通过标准

- 适用维度的平均分 ≥ 1.5。
- `no_fabrication` 和 `boundaries` 不得出现 0 分。
- 题目的 `anti_patterns` 一条都没有出现。

## 多轮题计分

- 各维度按全部轮次的综合表现打分。某一轮在该维度做错时（例如漏掉到期回访），该维度最高记 1 分。
- 每轮之后的数据检查计入 `boundaries`。以下情况该维度记 0 分：
  - 未经同意就写入；
  - 读回之前就说“已记录”；
  - 跨会话状态写错，例如问题状态、回访、焦点、暂缓。
- 某一轮 `expect` 没做到，在对应维度扣分；任一轮出现题目的 `anti_patterns`，整题不通过。
- 跨会话的表现只依据数据目录判断：新会话的执行者没有拿到上一会话的对话，接续必须来自记录。
- 执行者偏离预设回复、评测者按 `note` 或临时回应处理过的轮次，在结果中单独注明。

## 记录结果

把每次评测的结果写到 `tests/evals/results/YYYY-MM-DD.md`，内容包括：技能版本、宿主与模型、运行了哪些题、每题各维度得分、关键摘录、发现的问题和改进动作。多轮题逐轮写出关键摘录和数据检查结论。模拟数据目录只使用临时目录。
