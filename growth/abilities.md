# 能力模型

10 项能力描述 PM 在真实任务中做出的判断与行动。8 项基础能力适用于所有阶段；`domain_expertise` 和 `team_leadership` 分别是专家路线和负责人路线的主线能力，其他阶段按需观察。每项能力在各阶段的具体表现见[阶段路径](stages.md)。

记录使用英文 ID，对用户展示中文名。

## 基础能力

| ID | 能力 | 看什么 | 典型证据 |
|---|---|---|---|
| user_problem | 用户洞察与问题界定 | 分清现象、需求、原因和方案；把问题落到具体用户、场景和证据上 | 把一条“要做 X”还原成可验证的问题陈述 |
| business_value | 业务与价值判断 | 讲清用户收益、业务收益、成本与机会成本；区分事实与预期 | 说明一个需求值得投入的条件，并核对关键业务假设 |
| solution_design | 方案设计与技术判断 | 从用户任务和机制出发比较备选，覆盖流程、状态、边界与可行性 | 方案对比、流程或原型，与研发校准过的取舍 |
| data_validation | 数据分析与效果验证 | 核对口径、基线、人群与数据质量；区分相关与因果；设计验证 | 对一次指标变化给出竞争解释和取证计划 |
| strategy_prioritization | 策略取舍与规划 | 围绕目标排序，讲清代价和不做什么，按新证据调整节奏 | 资源受限时重排需求，说明先后与停止条件 |
| delivery_risk | 交付推进与风险控制 | 识别依赖、决策点与风险，定义验收标准，跟进到结果 | 风险清单与预案、灰度方案、上线回看 |
| communication_influence | 沟通协作与影响力 | 面向不同相关方表达判断、理解诉求、处理分歧、促成行动 | 评审材料、实际沟通产出与后续决策 |
| learning_transfer | 复盘学习与方法迁移 | 依据结果修正判断，提炼条件与边界，把方法用到新情境 | 间隔一段时间后，在新任务中独立用上旧方法 |

## 双轨主线能力

| ID | 能力 | 看什么 | 典型证据 |
|---|---|---|---|
| domain_expertise | 领域深度与方法输出 | 掌握会改变产品判断的领域机制、约束与术语；定义领域难题并沉淀可复用的方法 | 领域模型、对复杂问题的独立定义、被团队采用的方法或标准 |
| team_leadership | 团队领导与人才培养 | 设定方向与边界，分配责任与授权，给成员反馈，搭建协作机制 | 团队目标拆解、授权安排、对成员的具体反馈及其结果 |

专家路线以 domain_expertise 为主线，带人是可选项；负责人路线以 team_leadership 为主线，可以借助团队里的专家。team_leadership 只评价用户本人的行为；讨论团队成员时，聚焦用户可以怎么做。

## 区分相邻能力

- business_value 看“值不值得投入”，strategy_prioritization 看“整体如何取舍”。
- solution_design 看机制与体验如何成立，delivery_risk 看协作与风险如何落地。
- 表达不清一般记在 communication_influence；问题出在结构或机制本身时，记到对应能力。
- 一份产出可以关联多项能力，在回顾和报告中仍只算一个问题。

## 支持程度

每项能力对照“用户当前阶段的锚点”记录支持程度：

| ID | 程度 | 含义 |
|---|---|---|
| unobserved | 未观察 | 还没有用户本人的行为材料 |
| needs_support | 需要支持 | 借助提示或示范，能完成边界清楚的任务 |
| independent | 可以独立 | 自己选择方法、解释取舍，完成任务闭环 |
| stable | 复杂情境稳定 | 在不同的模糊或冲突情境中持续做到 |

某项能力在当前阶段达到 stable 后，下一阶段的锚点就是它新的成长目标，导师要明确告诉用户。各级升级需要的证据见[证据与记录](../reference/evidence-and-records.md)，由脚本校验。

升级一次一级，只有未观察可以直接升到可以独立，stable 只能从可以独立升上来。作为证据的每条记录都要有这项能力的观察（observations），不能拿为别的能力写的记录凑数。升到 stable 前先由 growth-reviewer 复核，结论写进记录的 `review`。

各项能力可以处在不同阶段，例如一位独立 PM 的数据能力已经达到资深要求。未观察的能力保持未观察；各项能力分别描述，不合成总分，也不据此推断职级。

## 个人扩展能力

用户想单独追踪某个维度（如伦理判断、系统架构理解、某个专业领域）时，先一起讨论它的含义和可观察行为，再注册为 `custom.<slug>`：

```json
{
  "id": "custom.ethics-judgment",
  "name": "伦理判断",
  "definition": "识别产品决策对用户和社会的潜在伤害，并在方案中设置保护",
  "observable_behaviors": ["在方案评审前主动列出可能受影响的人群与保护措施"]
}
```

```sh
python3 <skill-dir>/scripts/pmgrow.py --data-dir <data-dir> ability register --input -
```

含义发生实质变化时注册新 ID，旧证据保留原来的解释。扩展能力使用与内置能力相同的证据规则。
